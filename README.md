# حركة — Harka

منصة تعليمية عربية مستقلة لطلاب علوم الرياضة بجامعة أسيوط. مبنية بـ Next.js وReact وTypeScript، مع حسابات وجلسات وصلاحيات، وقاعدة SQLite محلية للحسابات والمحتوى وتقدّم الطلاب. لا تحتاج Supabase أو أي خدمة سحابية.

[النشر على Coolify](docs/coolify.md) · [دليل الرفع على GitHub](docs/github.md) · [هيكل المنتج](docs/architecture.md) · [ملفات الهوية البصرية](public/brand/README.md)

## التشغيل

المتطلبات: Node.js 24 أو أحدث، وnpm.

```powershell
npm ci
npm run dev
```

افتح http://127.0.0.1:3000. عند أول تشغيل افتح `/setup` وأنشئ حساب الإدارة بنفسك؛ لا توجد بيانات دخول افتراضية. يُغلق الإعداد بعد إنشاء أول مدير. بعدها يمكن إنشاء حسابات طلاب من `/register` والدخول من `/login`.

للتشغيل المحلي بعد البناء:

```powershell
npm run build
npm start
```

عند تشغيل `npm start` بقاعدة جديدة، اضبط `HARKA_SETUP_TOKEN` برمز عشوائي خاص لا يقل عن 32 حرفًا قبل إعداد المدير. التطوير المحلي بـ `npm run dev` لا يشترط الرمز إلا إذا ضُبط في البيئة.

أوقف خادم التطوير بـ Ctrl+C قبل تشغيل خادم آخر على المنفذ نفسه. كلا الأمرين يرتبط بـ 127.0.0.1 للتشغيل على الجهاز الحالي.

تعديل الملف الدراسي من صفحة الإعدادات فقط، بدون اختصارات مكررة في الهيدر أو الرئيسية. التسجيل العام ينشئ طالبًا فقط. الصلاحيات تُفحص على الخادم لكل صفحة وعملية API؛ إخفاء الأزرار ليس آلية الحماية. إيقاف الطالب ينهي جلساته المفتوحة. الإدارة لا تعرض كلمات المرور.

## البيانات المحلية

تُنشأ القاعدة تلقائيًا في `.data/harka.sqlite`. كلمات المرور محفوظة بتجزئة scrypt، والجلسات في ملفات ارتباط HttpOnly وSameSite=Lax. رمز الجلسة يُحفظ مجزّأً في القاعدة. لكل طالب محفوظات وتقدّم مستقلان.

حذف بيانات المتصفح لا يحذف الحسابات أو المحتوى من القاعدة. التفضيل الفاتح/الداكن فقط يُحفظ في المتصفح. بيانات النموذج القديم تحت `harka-local-v1` لم تُحذف، لكنها لا تُستورد تلقائيًا إلى الحسابات الجديدة.

للنسخ الاحتياطي محليًا: أوقف الخادم وانسخ مجلد `.data` كاملًا إلى مكان آمن. للاستعادة، أوقف الخادم أولًا ثم استعد المجلد. مجلد البيانات مستبعد من Git. يمكن تغيير مسار القاعدة عبر `HARKA_DATABASE_PATH` قبل تشغيل الخادم، ويجب إعادة التشغيل لتطبيقه.

## المحتوى المتاح

الفهرس يغطي 32 تركيبة للمسار والترم: الفرق الأربع، بنين وبنات، وشعب التدريس والتدريب والإدارة في الثالثة والرابعة. درس العزم النموذجي يحتوي شرحًا وتجربة واختبارًا. بقية الدروس تضيفها الإدارة وتنشرها. وجود المادة في الفهرس لا يعني اكتمال شرحها.

الدروس تدعم رابط YouTube اختياريًا، ولا يُحمّل المشغّل قبل الضغط على التشغيل. الخط العربي محفوظ محليًا. تشغيل الفيديو والمراجع الخارجية يحتاج الإنترنت.

المصادر: محاضرات 2025/2026 للترم الأول، امتحانات 2025/2026 للنظري بالترم الثاني، وبعض التطبيقات من محاضرات 2024/2025. هذه ليست مصادقة على لائحة 2026/2027. سنة المصدر تظهر داخل المقرر، وخيارات التخصص ليست كلها إلزامية لكل طالب.

- [جداول الكلية الرسمية](https://aun.edu.eg/physical_education/ar/stu/study%20schedules)
- [مرجع درس العزم: OpenStax](https://openstax.org/books/university-physics-volume-1/pages/10-6-torque)

## التحقق

```powershell
npm run repo:check
npm run typecheck
npm test
```

الاختبار يبني المشروع ويشغّل خادمًا منفصلًا على 3001، بقاعدة بيانات جديدة داخل `test-results`. يختبر الحسابات والجلسات والصلاحيات وفصل بيانات الطلاب ونشر الدروس والتقدم وإيقاف الحساب، ويراجع العرض بأحجام 320 و390 و768 و1440 بكسل. يغلق خادم الاختبار بعد الانتهاء ولا يغيّر قاعدة المنصة الحقيقية.

على Windows يستخدم الاختبار Chrome المثبّت. لتحديد متصفح آخر اضبط `HARKA_BROWSER_PATH` إلى ملف تنفيذه. على الأنظمة الأخرى ثبّت Chromium للاختبار عبر `npx playwright install chromium`. يمكن تغيير منفذ الاختبار بـ `HARKA_TEST_PORT`.

## حدود المرحلة

هذه بنية منتج تعمل محليًا. تأكيد البريد، استعادة كلمة المرور، واجهة الدكاترة، التقييمات الجامعية، والإشعارات ليست مفعّلة. فهرس المقررات يُعدّل في الكود؛ الإدارة الحالية تدير الدروس. قبل النشر العام نحتاج مراجعة حماية التشغيل والمصادقة وتأمين إعداد المالك، وHTTPS ونسخًا احتياطيًا واستضافة بيانات دائمة. لا توجد مدفوعات أو رسائل بريد أو اتصال بخدمات سحابية.

اقرأ [تفصيل الهيكل والصلاحيات والبيانات](docs/architecture.md) عند تطوير المرحلة التالية.

## تجربة الطالب المحدثة

القائمة الجانبية أصغر، بدون بطاقة ترويجية كبيرة، والتمرير رفيع مع الاحتفاظ بإمكانية التمرير. البطاقة الرئيسية مخصصة لـ32 تركيبة من الفرقة والفئة والشعبة والترم، وتفتح مقررًا من نفس المسار؛ تجربة العزم تظهر في المسارات التي تحتوي مقرر التحليل الحركي.

مقررات التخصص الجماعي والفردي تتيح اختيار الرياضة أثناء التسجيل أو من الإعدادات أو داخل المقرر. الاختيار محفوظ لكل طالب ومقرر، وعنوان البطاقة يتغير وفقًا له. الإدارة تستطيع إضافة درس مشترك أو تخصيصه لرياضة؛ الدروس المتخصصة ومواعيدها لا تُرسل لطالب لم يختر الرياضة. هذه اختيارات لتنظيم المنصة، وتُطابق توزيع الطالب الفعلي في الكلية. الخيارات ذات الأسماء المحددة في الفهرس تلتزم بها؛ المقررات العامة تعرض قائمة رياضات أوسع تحتاج مطابقة التوزيع الرسمي.

الجدول لا يحتوي مواعيد افتراضية منشورة. تنشر الإدارة جدولًا لكل مسار من `/admin/schedule`، مع العام الدراسي ومصدره؛ إلى أن يحدث ذلك تظهر حالة واضحة بأن الجدول غير منشور. المواعيد الموجودة في اختبارات المتصفح تجريبية فقط وتبقى بقاعدة الاختبار المنفصلة.

## المكتبة والتكليفات والاختبارات

- المكتبة: `/student/library`، وإدارتها `/admin/library`. كتب وملخصات ومراجع وأوراق عمل، بملف محلي أو رابط خارجي، مع بحث وتصنيف. الموارد مرتبطة بالمقرر والفئة والشعبة والترم والرياضة إن حُدّدت.
- التكليفات: `/student/assignments`، وإدارتها `/admin/assignments`. عنوان، صاحب التكليف، تعليمات، موعد، درجة نهائية وملف تعليمات اختياري. الطالب يسلّم نصًا أو رابطًا أو ملفًا، ويمكن التعديل قبل الموعد والتصحيح. الإدارة تصحح بدرجة وملاحظات، أو تعيد التسليم للمراجعة.
- الاختبارات: `/student/exams`، وإدارتها `/admin/exams`. أسئلة اختيار من متعدد، أربع إجابات لكل سؤال، درجة وتفسير، مدة، عدد محاولات ونسبة اجتياز، ومواعيد إتاحة اختيارية. إجابات الطالب محفوظة على الخادم، ونتيجة المحاولة تشمل مراجعة الأسئلة بعد انتهائها.
- الملفات: PDF وDOCX وPNG وJPG حتى 20 ميجابايت لكل ملف. تُحفظ في SQLite مع بقية البيانات؛ لا تحتاج مجلد رفع أو خدمة تخزين منفصلة. التنزيل محمي بالجلسة والصلاحيات. ملفات تسليم الطالب لا تظهر لطالب آخر.
- الوقت لا يتوقف عند تحديث الصفحة أو إغلاقها. المحاولة المنتهية تُصحح من الإجابات المحفوظة على الخادم عند الطلب التالي. إرسال الدرجة من المتصفح لا يغيّر التصحيح.
- إجابة السؤال الصحيحة وتفسيرها لا تُرسلان للطالب أثناء المحاولة. الاختبار الذي بدأ فيه الطلاب لا يُعدّل ولا يُحذف؛ الإدارة تنشئ نسخة جديدة للحفاظ على نتائج النسخة السابقة.
- لكل تكليف تسليم حالي واحد لكل طالب. الإعادة للمراجعة لا تمدد الموعد تلقائيًا؛ الإدارة تستطيع تعديل موعد التكليف. التكليف الذي له تسليمات لا يُحذف، ويمكن تحويله لمسودة.
- أدوات الإدارة حاليًا هي نقطة النشر والتصحيح. اسم الدكتور صاحب التكليف حقل تعريفي، وليس حساب دكتور مفعّلًا. الدرجات تخص تجربة المنصة وليست ربطًا بنظام درجات الجامعة.

لا تُملأ النسخة الحقيقية بكتب أو تكليفات أو اختبارات افتراضية؛ محتوى الاختبارات الآلية يبقى في قواعد اختبار منفصلة.

## جدول الفرقة الثالثة 2026/2027 — الترم الأول

أُضيفت الجداول التي قدمها مالك المنصة في المحادثة للأقسام: التدريب الرياضي، المناهج وطرق التدريس، والإدارة الرياضية، بنسخ منفصلة للبنين والبنات. بيانات النسخ الست في `data/third-year-2026-2027.cjs`. تمثل 94 خانة قبل تصفية الرياضات المختارة. المصدر مسجل كمحتوى مقدم من المالك؛ لم يُنسب إلى رابط رسمي غير مقدم.

الأنشطة غير المطابقة لمقرر مفهرس تحفظ بعناوين مستقلة. الأماكن غير المذكورة تبقى فارغة وتعرض بوضوح. توزيع المجموعات غير المحدد محفوظ كملاحظة. وقت «12–2 وما بعدها» يظهر بالنص الأصلي، دون افتراض نهاية لجميع مجموعات اليوم. الأيام الخالية كما وردت محفوظة في ملاحظات الأيام. الاستثناءات مثل «ما عدا السباحة» تُطبق على اختيار الطالب.

لإعادة إدخال المصدر بعد تهيئة القاعدة بالحساب الإداري وتشغيل النسخة المحدثة مرة واحدة:

```powershell
npm run schedule:import
```

هذا الأمر يحدث الجداول الستة المستهدفة من المصدر، وقد يستبدل تعديلات الإدارة اليدوية عليها. لا يعمل تلقائيًا عند بدء الخادم، ولا يغيّر جداول الفرق أو الفصول الأخرى. يمكن تعديل النسخ المنشورة من `/admin/schedule`.

## عرض جدول الطالب

صفحة `/student/schedule` تعرض اليوم افتراضيًا، مع بطاقة للمحاضرة الحالية أو القادمة، وتقويم أسبوعي قابل للتنقل، وخط زمني يميز النظري والعملي والفواصل بين المحاضرات. يمكن عرض الأسبوع كاملًا والبحث باسم المادة أو المكان أو المحاضر وتصفية نوع المحاضرة. تفاصيل المجموعات داخل أقسام قابلة للفتح، والطباعة تتبع العرض المختار.

حساب اليوم والمحاضرة التالية يعتمد على توقيت `Africa/Cairo` والتوقيت الصيفي، مع عرض المواعيد بنظام 12 ساعة. التقويم يعرض تكرار الجدول الأسبوعي؛ لا يمثل تقويم إجازات أو إلغاءات محاضرات. اختبارات المتصفح تراجع العرض من 320 إلى 1440 بكسل، وتتحقق من البحث والفلاتر والتنقل بالكيبورد والوضع الداكن والطباعة، وتراجع اختبارات الحسابات حدود اليوم والأسبوع والسنة.

## مساحة المادة ومسار التعلّم

صفحة المادة أصبحت مركزًا يضم التعلّم والملفات والتكليفات والاختبارات الخاصة بنفس المقرر. تعرض الوحدات والدروس بالترتيب الذي تحدده الإدارة، مع حالة الإكمال والرجوع إلى آخر درس مفتوح غير مكتمل. لا تُنشأ وحدات أو مدد أو دروس افتراضية للمقررات الخالية.

من `/admin/content` يمكن ضبط عنوان الوحدة وترتيبها وترتيب الدرس والمدة بالدقائق (0 لإخفائها)، وإضافة خلاصة وتطبيق وسؤال تدريب بثلاثة اختيارات وتفسير للإجابة. يمكن تقسيم الشرح بعناوين تبدأ بـ `##`، وفصل الفقرات بسطر فارغ. سؤال التدريب داخل الدرس منفصل عن الاختبارات المحسوبة ولا يُسجل درجة.

شاشة الدرس تعرض فيديو YouTube عند تشغيله فقط، وشرحًا منظمًا وخلاصة وتطبيقًا وسؤال الفهم حسب المحتوى المُضاف، مع مراجع المادة والتنقل للدرس السابق والتالي. فتح الدرس يُحفظ كآخر زيارة، ولا يسجّل الإكمال تلقائيًا. إكمال الدرس عملية صريحة محفوظة على الخادم.

هجرة SQLite إلى الإصدار 5 تضيف تنظيم الدروس وآخر زيارة دون حذف المحتوى أو الحسابات. الدروس ومساراتها المباشرة محصورة في الفرقة والفئة والشعبة والترم والرياضة المناسبة للطالب. المسودات تظل خاصة بالإدارة. اختبارات `check-course.cjs` تعمل على قاعدة مستقلة وتغطي التحرير والترتيب والتقدم والزيارات وفصل الحسابات والمحتوى والتبويبات والبحث والموبايل والوضع الداكن.

## تجهيز المستودع

الفرع المحلي `main`، مع تجاهل البيانات الخاصة ومخرجات البناء، وتثبيت الاعتماديات في ملف القفل. مهمة GitHub Actions تفحص المستودع والأنواع والبناء واختبارات المتصفح بقواعد بيانات منفصلة. الخطوات الأولى لإعداد هوية Git وربط المستودع والرفع موجودة في [دليل GitHub](docs/github.md).

## النشر على haraka.seif4d.com

يوجد Dockerfile لـNode.js 24 وNext.js standalone، يشغّل التطبيق كمستخدم غير root على `0.0.0.0:3000`. إعدادات الدومين وDNS وHTTPS وvolume والمتغيرات وإنشاء المدير واستيراد الجداول موجودة في [دليل Coolify](docs/coolify.md). صورة الإنتاج لا تشمل قاعدة جهازك أو ملفات البيئة أو نتائج الاختبارات. قاعدة الخادم تحتاج volume على `/app/.data`.

`/api/health` يفحص جاهزية التطبيق وقاعدة البيانات دون عرض بيانات خاصة. `npm run db:backup` ينشئ نسخة SQLite متسقة. بناء صورة الإنتاج وفحص استمرار البيانات بعد استبدال الحاوية يتمان في مهمة GitHub Actions مستقلة. النشر على خادمك تنفذه بنفسك من Coolify.

## صورة مشاركة الرابط

`public/brand/harka-share-v1.png` صورة Open Graph بمقاس 1200×630، مع إبقاء الشعار والنص داخل المربع الأوسط لتناسب المعاينات المقصوصة. تُستخدم في Open Graph وTwitter Cards برابط مطلق حسب `HARKA_PUBLIC_ORIGIN`، مع العنوان والوصف الحاليين من إعدادات الإدارة. الصورة عامة ولا تحتاج جلسة أو توليدًا عند الطلب.

لإعادة توليدها من الشعار والخط المحليين: `node scripts/render-share-card.cjs`. الاختبارات تتحقق من بيانات المعاينة لوكلاء WhatsApp وFacebook ومن مقاس وصيغة وحجم الصورة وإتاحتها في صورة الإنتاج. تغيير صورة المشاركة لاحقًا يحتاج اسم ملف جديد أو إصدارًا جديدًا للرابط؛ تطبيقات المحادثات قد تحتفظ بمعاينة سابقة للرابط نفسه.

## الدروس التفاعلية

من إدارة المحتوى، يمكن بناء الدرس من وحدات قابلة للترتيب: شرح، استكشاف ومقارنة، بطاقات كشف، أسئلة بتفسير، ترتيب خطوات ومعامل تفاعلية. المحرر يعاين نفس تفاعل الطالب، ويحفظ الوحدات مع حالة المسودة أو النشر والمسار الدراسي. الدروس القديمة مستمرة، ومثال التدريب متاح داخل المحرر. [تفاصيل التأليف والبيانات والمثال](docs/interactive-lessons.md).
