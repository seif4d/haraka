# رفع حركة على GitHub

جذر المشروع والمستودع هو مجلد `harka` نفسه. مجلد البحث المجاور ليس جزءًا من التطبيق.

## ما يدخل المستودع

شفرة التطبيق، `package.json` و`package-lock.json`، ملفات الشعار والخط وترخيصه، مصدر جداول الفرقة الثالثة، التوثيق، والاختبارات. لا تدخل الحسابات أو المحتوى المحلي أو الملفات المرفوعة أو النسخ الاحتياطية: كل ذلك داخل `.data` المستبعد من Git، كما تُستبعد `.next` و`node_modules` ونتائج الاختبارات وملفات البيئة الخاصة.

قبل كل رفع:

```sh
npm run repo:check
npm run typecheck
npm test
```

`repo:check` يراجع أسماء الملفات المجهزة وغير المتتبعة، وأحجامها، وأنماط بعض المفاتيح الشائعة. يظل فحص الفرق قبل الرفع مطلوبًا عند إضافة إعدادات أو بيانات جديدة؛ الفحص ليس ماسح أسرار شاملًا.

## أول رفع

المستودع المحلي مهيأ على `main`. حدّد هويتك الحقيقية لهذا المستودع إذا لم تكن مضبوطة، واستبدل القيم التالية ببياناتك:

```sh
git config user.name "YOUR_NAME"
git config user.email "YOUR_GITHUB_EMAIL"
git add .
git diff --cached --stat
git commit -m "Initial commit: Harka learning platform"
```

أنشئ مستودع GitHub فارغًا باسم تختاره، دون إضافة README أو ترخيص تلقائي، ثم انسخ عنوانه:

```sh
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

لا تحفظ رموز GitHub في عنوان المستودع أو داخل الملفات. استخدم تسجيل دخول GitHub المعتاد أو مفتاح SSH المحلي. هذان الأمران هما خطوة الرفع الفعلي؛ تجهيز المشروع المحلي لا ينشئ مستودعًا على حسابك ولا ينشر الموقع.

## الفحص على GitHub

ملف `.github/workflows/ci.yml` يعمل عند الرفع إلى `main` وفتح Pull Request، ويمكن تشغيله يدويًا. يثبت الاعتماديات من ملف القفل، ويفحص محتويات المستودع وTypeScript، ويثبت Chromium ثم يبني المشروع ويشغّل اختبارات المنتج وترقية قاعدة البيانات. الاختبارات تنشئ قواعد منفصلة داخل `test-results`؛ لا تحتاج بيانات الدخول أو قاعدة جهازك. صلاحيات المهمة للقراءة، وإصدارات إجراءات GitHub مثبتة بمعرفات commits.

مراجع إعداد المهمة: [checkout](https://github.com/actions/checkout)، [setup-node](https://github.com/actions/setup-node)، [Playwright CI](https://playwright.dev/docs/ci-intro).

## تشغيل نسخة مستنسخة

```sh
npm ci
npm run dev
```

افتح `http://127.0.0.1:3000/setup` وأنشئ حساب الإدارة. الحسابات والمحتوى المحلي يبدأان بقاعدة جديدة؛ بيانات الجهاز الأصلي لا تُنقل عبر GitHub. بعد إعداد المدير، يمكن إدخال الجداول الستة من المصدر المحفوظ:

```sh
npm run schedule:import
```

الاستيراد يستهدف جداول الفرقة الثالثة للترم الأول 2026/2027، ويستبدل تعديلاتها اليدوية عند إعادة تشغيله. الملفات والدروس والتكليفات والاختبارات تُضاف وتُنشر من الإدارة.

## إعدادات البيئة

التشغيل الافتراضي لا يحتاج مفاتيح أو خدمات سحابية. `.env.example` مثال آمن؛ انسخه إلى `.env.local` فقط لتغيير مسار SQLite أو إعدادات التشغيل الاختيارية. عند استعمال مسار SQLite مختلف، اضبط `HARKA_DATABASE_PATH` نفسه أيضًا في جلسة تشغيل سكربت الاستيراد.
