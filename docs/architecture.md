# هيكل المنتج المحلي

## الرحلة

الزائر يفتح `/` للتعريف بالمنصة، ثم `/register` لإنشاء حساب طالب أو `/login` للدخول. أول تشغيل يحتاج إعداد المالك من `/setup` مرة واحدة؛ يغلق المسار بعد إنشاء الإدارة. لا توجد كلمات مرور افتراضية أو حسابات جاهزة.

الطالب يدخل `/student`، ويصل إلى المقررات والدروس ومحفوظاته وتقدّمه من روابط مستقلة يمكن تحديثها وفتحها مباشرة. الإدارة تدخل `/admin` وتدير المحتوى والطلاب. الدخول بحساب من دور مختلف يعيد المستخدم إلى مساحته. الزائر غير المسجل يُوجّه للدخول.

## الحدود والمسؤوليات

| الطبقة | الملفات | مسؤوليتها |
| --- | --- | --- |
| المسارات العامة | `app/page.tsx`, `app/login`, `app/register`, `app/setup` | التعريف والدخول والتسجيل والإعداد الأول |
| مسارات الطالب | `app/student/*`, `components/student-screen.tsx` | التحقق من الدور وتحميل البيانات المسموح بها |
| مسارات الإدارة | `app/admin/*`, `components/admin-screen.tsx` | التحقق من دور الإدارة وتحميل أدواتها |
| الواجهات | `components/public-site.tsx`, `auth-form.tsx`, `harka-app.tsx`, `admin-app.tsx` | العرض والتفاعل وإظهار نجاح أو فشل الحفظ |
| الأنواع | `lib/domain.ts` | المستخدم والأدوار والدرس وحالة النشر |
| فهرس المقررات | `lib/curriculum.ts`, `lib/catalog.ts` | توزيع المواد ومعرّفاتها المستقرة وبيانات مصدرها |

| المصادقة | `lib/server/auth.ts` | تجزئة كلمات المرور وإصدار الجلسات وإنهاؤها |

ملفات `lib/server` محمية بـ `server-only`. مكونات المتصفح لا تصل إلى قاعدة البيانات أو تجزئات كلمات المرور. حراسة الصفحات لرحلة الاستخدام؛ الحماية الأساسية موجودة أيضًا في API لكل طلب، ولا تعتمد على إخفاء زر في المتصفح.

## البيانات

| الجدول | العلاقة والاستخدام |
| --- | --- |
| `users` | البريد الفريد، تجزئة كلمة المرور، الدور، المسار الدراسي، حالة الحساب |
| `sessions` | تجزئة رمز جلسة عشوائي، معرّف المستخدم، وقت انتهاء بعد سبعة أيام |
| `lessons` | المقرر، المؤلف، العنوان والمقدمة والشرح ورابط الفيديو، حالة مسودة أو منشور |
| `bookmarks` | محفوظات خاصة بالمستخدم؛ مفتاح مركب يمنع التكرار |
| `progress` | إكمال الدرس لكل مستخدم، مع وقت الإكمال |
| `auth_attempts` | حد لمحاولات المصادقة لكل بريد وإجراء: 10 خلال 15 دقيقة |
| `audit_log` | إعداد الإدارة والتسجيل وتعديلات المحتوى وحالة الطلاب |

فهرس المقررات الحالي يُدار في الكود، وليس جدولًا قابلًا للتحرير من الإدارة. معرّف المقرر يراعي المسار والفئة والترم؛ لذلك نشر درس في مقرر للبنات لا يضيفه تلقائيًا إلى مقرر آخر للبنين. واجهة الطالب تعرض مساره وتسمح بتغييره؛ تصفّح المسارات ليس اشتراكًا مدفوعًا أو قيد وصول أكاديمي.

## النشر والصلاحيات

- التسجيل العام يحدد `student` على الخادم مهما كانت حقول الطلب؛ لا يوجد حقل يسمح للمسجّل باختيار الإدارة.
- إعداد الإدارة يتم داخل معاملة تعيد التحقق من عدم وجود مدير، لمنع إعداد مديرين بالتزامن.
- الإدارة تنشئ الدرس كمسودة افتراضيًا، ثم تنشره عمدًا. المسودة لا تُرسل لبيانات الطالب، ورابطها المباشر يُرجع 404.
- الإدارة تستطيع تعديل أو حذف الدرس ومعاينته. حذف الدرس يحذف تقدّمه المرتبط داخل معاملة واحدة.
- إيقاف طالب يحذف جلساته المفتوحة. كل طلب يتحقق من أن الحساب ما زال نشطًا.
- لا تُعرض كلمات المرور أو تجزئاتها في واجهة الإدارة أو API.
- الدور `instructor` موجود في الأنواع وقيد قاعدة البيانات، مع مسار محمي محجوز. لا يمكن التسجيل به أو تعيينه من الواجهة الحالية؛ أدوات الدكاترة تحتاج تنفيذًا مستقلًا.

## الحماية المحلية

كلمات المرور تُجزّأ باستخدام scrypt مع ملح عشوائي. رمز الجلسة عشوائي بطول 32 بايت؛ يُحفظ رمزه في ملف ارتباط HttpOnly وSameSite=Lax، وتحفظ القاعدة تجزئته فقط. Secure يعمل عند استخدام HTTPS، أما التشغيل المحلي فهو HTTP على 127.0.0.1.

طلبات الكتابة تتطلب Origin مطابقًا للمضيف وJSON. الاستعلامات تستخدم معاملات مهيّأة، والمدخلات لها حدود أطوال، وروابط الفيديو تُقبل من YouTube فقط. بيانات API تُرسل مع `Cache-Control: no-store`. إنجاز درس العزم يتحقق من الإجابة على الخادم؛ هذا تقدّم تعليمي وليس نظام درجات رسميًا.

هذا أساس محلي وليس تصريحًا بالنشر العام. قبل النشر نحتاج تأكيد البريد واستعادة كلمة المرور، ومراجعة المصادقة وحدود المحاولات على مستوى عنوان الشبكة، وإغلاق الإعداد الأول بمفتاح مالك أو إجراء تشغيل آمن، وHTTPS ونسخًا احتياطيًا واستضافة بيانات دائمة. تحديد صلاحيات الدكاترة وتكليفهم بالمقررات يأتي قبل تفعيل دورهم. النظام الحالي لا يرسل بريدًا ولا يتصل بخدمة سحابية.

## الاختبار

`npm test` يبني المشروع، ثم يشغّل خادم اختبار منفصلًا على 3001 مع قاعدة جديدة تحت `test-results`. ينشئ بيانات مؤقتة، ويختبر تسجيل الحسابات ودخولها وخروجها، فصل بيانات طالبين، الصلاحيات المباشرة في API، دورة مسودة/نشر، القراءة والاختبار والتقدم، إيقاف الحساب، رفض Origin مخالف، تجزئة كلمات المرور، وأبعاد الصفحات على الموبايل والكمبيوتر. يغلق خادم الاختبار عند الانتهاء. قاعدة المنصة `.data/harka.sqlite` لا تدخل في هذه الاختبارات.

## تحديث تجربة الطالب: التخصصات والجداول

- `/student/settings` هو مكان تعديل المسار بعد التسجيل؛ الرئيسية والفهرس لا يكرران أدوات تغيير الملف الدراسي.
- `lib/student-feature.ts` يختار فكرة ومقررًا من نفس الفرقة والترم والشعبة والفئة. المثال التفاعلي للعزم لا يحول الطالب لمسار آخر.
- `specializations` يربط المستخدم ومعرّف مقرر التخصص برياضة واحدة. الاختيار منفصل لكل مسار وترم، ويُحفظ عند الانتقال بينهما. تغيير التخصص لا يحذف تاريخ التقدم القديم.
- الهجرة إلى إصدار القاعدة 2 تضيف جداول التخصصات والجداول، وعمود `sport_id` للدروس الحالية بقيمة فارغة؛ تبقى الدروس السابقة مشتركة وتُحفظ الحسابات والجلسات.
- `lessons.sport_id` الفارغ يعني درسًا مشتركًا. القيمة المحددة تُرشَّح على الخادم حسب اختيار الطالب في نفس المقرر، بما في ذلك الرابط المباشر وطلب تسجيل الإكمال.
- `schedules` يحفظ أحدث جدول لمسار محدد بمفتاح الفرقة والفئة والشعبة والترم. يحتوي العام الدراسي والمصدر والحالة ومدخلات الأسبوع. المسودة لا تظهر للطالب.
- كل محاضرة مرتبطة بمقرر في المسار، واليوم والوقت والمكان والنوع والمحاضر الاختياري. يمكن ربطها برياضة معينة؛ فتُرشّح للطالب على الخادم أيضًا.
- إدارة الجدول في `/admin/schedule`. لا تُملأ قاعدة المنصة الحقيقية بمواعيد اختبار أو مواعيد مفترضة.
- الاختبارات تغطي تخصيص 32 مسارًا، غياب أدوات الملف الدراسي المكررة، عرض القائمة المضغوطة، اختيار الرياضة وحفظها، رفض رياضة لا تنتمي للمقرر، فصل دروس رياضتين وروابطهما، مسودة الجدول ونشره وتصفية المواعيد حسب التخصص والمسار.

## الوحدات الأكاديمية: إصدار قاعدة البيانات 3

`lib/academic-domain.ts` يعرّف الموارد والتكليفات والتسليمات والاختبارات والمحاولات. `lib/server/academic.ts` يطبق التحقق من البيانات والصلاحيات ودورة التسليم والتصحيح. `academic-http.ts` يربطها بطلبات API، ومكونات الطالب والإدارة منفصلة في `student-learning.tsx` و`student-exam.tsx` و`admin-learning.tsx`.

الجداول الجديدة: `files` للملفات الثنائية ومالكها واستخدامها؛ `library_items` لموارد المكتبة؛ `assignments` للمطلوب والموعد؛ `submissions` لتسليم الطالب ومراجعته؛ `exams` لإعدادات الاختبار وأسئلته؛ `exam_attempts` لمحاولات الطالب. التهيئة تضيف الجداول دون حذف الحسابات أو البيانات السابقة.

التوزيع يعتمد على معرّف مقرر ثابت، ويطابق الفرقة والفئة والشعبة والترم الحالي. الرياضة المحددة تُطابق اختيار الطالب في نفس المقرر. كل مورد أو تكليف أو اختبار يبدأ كمسودة. المحتوى غير المنشور أو من مسار آخر لا يظهر في بيانات الطالب؛ الرابط المباشر للتكليف غير المسموح يُرجع 404.

رفع الملفات منفصل في `/api/files` بطلب multipart محدود الحجم. تُفحص امتدادات وتواقيع PDF وDOCX وPNG وJPG، ويُشتق نوع الملف على الخادم. الملف لا يُنفّذ ولا يُفك ضغطه؛ التنزيل في `/api/files/[id]` مرفق محمي بالجلسة مع منع التخمين بمُعرّف عشوائي. ملفات المحتوى تُرفع بواسطة الإدارة فقط. ملف التسليم مرتبط بصاحبه وتكليفه، ولا يمكن لطالب إرفاق ملف طالب آخر. الملفات اليتيمة من إلغاء نموذج تبقى خاصة بمالكها؛ تنظيفها والحصص التخزينية مرحلة تشغيل لاحقة.

التسليم له قيد فريد على الطالب والتكليف. التعديل يعيد الحالة إلى submitted ويزيل ملاحظات المراجعة السابقة؛ يُرفض إذا انتهى الموعد أو اكتمل التصحيح. المراجعة تحصر الدرجة بين صفر والدرجة النهائية. تغيير مسار تكليف له تسليمات أو حذف التكليف يُرفض. لا يُخفض الحد الأعلى تحت درجة سابقة.

المحاولة تأخذ نسخة ثابتة من الأسئلة ونسبة الاجتياز عند بدايتها. يوجد فهرس فريد يمنع أكثر من محاولة جارية لنفس الطالب والاختبار. طلب البداية المتكرر يعيد نفس المحاولة. البداية تُراجع نافذة الإتاحة وعدد المحاولات والمسار. إجابات الطالب تُحفظ كخريطة معرّفات أسئلة إلى أرقام الاختيارات، مع رفض السؤال أو الاختيار غير الموجود. وقت النهاية هو الأقرب من نهاية المدة ونهاية الإتاحة.

DTO الطالب قبل التسليم لا يحتوي correctIndex أو explanation. النتيجة تُحسب على الخادم من نسخة الأسئلة. عند انتهاء الوقت تُصحح الإجابات المحفوظة، ولا تُقبل إجابات متأخرة. تسليم محاولة منتهية مرة أخرى يعيد نتيجتها نفسها دون تغيير. محاولات الآخرين وروابطها لا تُتاح للطالب. لا يُعدّل أو يُحذف اختبار له محاولات، وتتيح الإدارة إنشاء نسخة جديدة. لا يوجد مؤقت خلفي دائم؛ الإنهاء التلقائي على الخادم يحدث عند الطلب التالي للمحاولة أو بياناتها.

الاختبار الآلي يغطي رفع وتنزيل ملف، رفض ملف مزيف وصلاحية رفع خاطئة، إخفاء موارد المسارات الأخرى، خصوصية ملفات التسليم، إعادة التكليف وتصحيحه وحدود الدرجة والموعد، حفظ إجابات الاختبار بعد التحديث، عدم تسريب الإجابات قبل التسليم، التصحيح الفعلي رغم محاولة تزوير الدرجة، انتهاء الوقت وحد المحاولات وخصوصية المحاولات، وأبعاد الصفحات في الموبايل والكمبيوتر. جميع البيانات في قاعدة الاختبار المنفصلة.

## جداول الفرقة الثالثة المستوردة — الإصدار 4

الجداول الستة لعام 2026/2027، الترم الأول، محفوظة في مصدر بيانات صريح ومستوردة داخل معاملة واحدة. السنة والترم أكدّهما المستخدم. `scripts/import-third-year-schedules.cjs` يحدث المفاتيح الستة فقط ويسجل import_user_schedule في سجل النشاط. لا ينشئ حسابات أو يغير بيانات الطلاب.

عمودا schedules.notes وschedules.day_notes يضافان بهجرة تحفظ البيانات السابقة. ScheduleEntry يدعم title وnotes وtimeLabel وexcludedSportIds. معرّف مقرر فارغ مسموح لنشاط مستقل بعنوان واضح؛ لا يربط نشاطًا بمقرر مختلف فقط لملء الفهرس. يطبق الخادم الاستثناءات والإيجابيات وفق اختيار الرياضة، ويحتفظ بالتوضيحات غير المحسومة بدل تخمين مجموعات الطالب. محرر الإدارة يعرض هذه الحقول ويحفظها.

## مساحة المادة والدرس — الإصدار 5

`lessons.structure` يخزن حقول `LessonDetails`: عنوان الوحدة وترتيبها، ترتيب الدرس، مدة اختيارية، خلاصة، تطبيق، وسؤال تدريب اختياري. تُضاف هذه البيانات بهجرة غير هدّامة، وتُدمج القيم الافتراضية للدروس السابقة عند القراءة. `lesson-details.ts` يتحقق من الحدود والأعداد وثلاثة اختيارات مختلفة وإجابة صحيحة وتفسير، ويحافظ على الحقول السابقة إذا أغفلها طلب تعديل قديم.

الوحدات تُشتق من الدروس المنشورة وترتيبها داخل المقرر؛ العنوان وترتيب الوحدة يحددان المجموعة. لا توجد وحدات وهمية أو مقفلة بانتظار المحتوى. `course-learning.ts` يوفر ترتيب الخطوات وتجميع الوحدات واختيار خطوة المتابعة وتجزئة الشرح إلى أقسام آمنة من النص، دون تنفيذ HTML. درس العزم المدمج يظهر فقط في المقررات التي تسمح به.

`lesson_visits` يحفظ آخر درس لكل طالب ومقرر، مستقلًا عن `progress`. مسار POST `/api/student/lesson-visit` يقبل فقط درسًا متاحًا لمسار الطالب ورياضته أو التجربة المدمجة المناسبة. المتابعة تختار آخر درس متاح غير مكتمل، ثم أول درس غير مكتمل، ثم أول درس للمراجعة. حذف الدرس يحذف الزيارات المرتبطة به؛ تحويله لمسودة أو تغيير الرياضة يجعل المتابعة تتجاوز الدرس غير المتاح.

`studentData` يصفّي الدروس على الخادم حسب معرّفات مقررات مسار الطالب والرياضة المختارة. روابط المواد والدروس والتجارب خارج المسار ترجع 404. مكوّن `course-hub.tsx` يجمع التعلّم وموارد وتكليفات واختبارات نفس المقرر، ويعيد استخدام وظائف الأقسام الأكاديمية القائمة. `course-lesson.tsx` يعرض الشرح وأقسامه والخلاصة والتطبيق وسؤال التدريب والمراجع والتنقل. مراجع شاشة الدرس تخص المادة كاملة وليست مرفقات خاصة بالدرس.

سؤال التدريب داخل الدرس متاح بكامل تفسيره للطالب لتثبيت الفهم، ولا يمنح درجة ولا يغيّر إجابات الاختبارات المحسوبة. الاختبارات تحتفظ بسياسة إخفاء الإجابات والتصحيح على الخادم كما سبق. الزيارة لا تسجل إكمالًا، والإكمال لا يدعي مشاهدة فيديو YouTube كاملًا أو قياس زمن القراءة.


## إعداد الإنتاج على Coolify

`HARKA_PUBLIC_ORIGIN` يحدد أصل الطلب المسموح خلف بروكسي إنهاء TLS، ويُستخدم أيضًا لاختيار Secure لجلسات HTTPS. الأصل لا يُشتق من `X-Forwarded-Host` أو `X-Forwarded-Proto` المرسل من العميل. يُطبق نفس الفحص على طلبات JSON وmultipart. عند التشغيل المحلي دون القيمة يُستخدم أصل URL الطلب المباشر.

إنشاء أول مدير في production يحتاج `HARKA_SETUP_TOKEN` خاصًا بطول 32–256 حرفًا. المقارنة بتجزئة ثابتة الحجم وtimingSafeEqual؛ الرمز لا يُرسل مع الصفحة أو يُخزن كجزء من حساب المدير. شرط عدم وجود مدير يعاد فحصه داخل المعاملة، ويغلق الإعداد بعد الحساب الأول.

Standalone يُفعّل عبر `HARKA_STANDALONE=1` أثناء بناء Docker فقط. الصورة النهائية تستخدم مستخدم node ومسار بيانات مطلقًا داخل volume، ولا تنسخ بيانات الجهاز أو أسراره. start-container يتحقق من أصل HTTPS ورمز الإعداد وإمكانية الوصول إلى مجلد البيانات قبل بدء الخادم. فحص الجاهزية يفتح قاعدة البيانات ويعيد حالة عامة. سكربت النسخ يستخدم Node SQLite backup لأخذ نسخة متسقة من القاعدة النشطة.

الاختبارات المحلية تحاكي متصفح HTTPS متصلًا بخادم HTTP داخلي، وتراجع حماية الإعداد والجلسات ورفع الملفات واستمرار البيانات. فحص الحاوية في CI يتحقق من الصورة الفعلية على Linux ومن استيراد المصدر والنسخ الاحتياطي وإعادة إنشاء الحاوية فوق volume نفسه.
